一、项目目标
----------------------------------------------------------------
现有内容：解剖学 / 生理学 / 病理学 / 药理学 四门课网页
目标：在现有网页基础上，加入用户系统 + 兑换码解锁功能
变现渠道：小红书挂商品卖兑换码 → 用户去网站注册 → 输入兑换码 → 自动成为VIP
内容方向：长期专注医学类资料，按系列出课（基础医学系列、护理系列等）

二、核心策略（已确认）
----------------------------------------------------------------
✅ 登录方式：邮箱 + 密码（零成本，简单）
✅ 免费内容：每门课开放前 2 章，其余章节锁定（共48章，免费8章）
✅ 收费方式：小红书卖兑换码，网站内不做在线支付，无需支付页面
✅ 域名：继续用 xiaowu-medical.netlify.app（免费）
✅ 防传播：必须登录账号才能看付费内容，兑换码一次性，账号绑定
✅ 发货：小红书下单 → 你手动发兑换码 → 买家去网站注册+兑换

三、定价策略（已确认）
----------------------------------------------------------------
套餐A：四门课全解锁（基础医学系列）  9.9元  永久有效  主推
套餐B：单门课解锁                    3.9元  永久有效  可选

定价逻辑：
- 9.9元主推：便宜、冲动消费、转化率高
- 3.9元单科：让犹豫的人先试水，后续引导买全套
- 不做月会员：内容固定，月付没有说服力
- 购买后内容持续维护更新，老用户永久享受更新内容

四、技术选型（已确认）
----------------------------------------------------------------
前端：
- 现有：纯静态 HTML + CSS + JS
- 新增：login.html / register.html / redeem.html / account.html / auth.js
- 托管：Netlify（现有，免费）

用户系统 + 数据库：
- 平台：LeanCloud（国内，免费，中文文档）
- 功能：用户注册登录、存储VIP状态、兑换码验证、管理员改权限

支付：
- 平台：小红书平台自带收款（无需对接第三方支付）
- 逻辑：收款在小红书完成，网站只做兑换码验证，两者完全分离

整体技术栈：
静态网页（Netlify）+ LeanCloud（用户+数据库+兑换码验证）
不需要虎皮椒，不需要支付页面

五、用户数据结构（LeanCloud）
----------------------------------------------------------------
用户表 _User：
  objectId        系统自动生成唯一ID
  email           邮箱（登录账号）
  password        密码（LeanCloud自动加密存储）
  is_vip          是否已付费（true / false）
  unlocked        已解锁课程列表，数组格式
                  示例：["medical4"] 或 ["anatomy","physiology"]
  redeemed_at     兑换时间
  createdAt       注册时间

兑换码表 RedeemCode：
  objectId        系统自动生成
  code            兑换码字符串（如：XW-A8K2-9J3M）
  type            对应套餐（medical4=基础医学四门 / anatomy=单科解剖 等）
  is_used         是否已被使用（true / false）
  used_by         使用者的 objectId（兑换后写入）
  used_at         使用时间

课程注册表 CourseList（扩展用）：
  course_id       课程唯一标识（如 anatomy / biochemistry）
  course_name     课程名称
  series          所属系列（medical_basic / nursing 等）
  free_chapters   免费章节数（默认2）
  is_active       是否已上线（true/false）
  price_single    单科定价

六、完整业务流程
----------------------------------------------------------------
购买流程：
用户在小红书看到笔记/商品
  → 下单购买（9.9元全套 / 3.9元单科）
  → 小红书确认收款
  → 你在 LeanCloud 后台生成一个唯一兑换码
  → 小红书发货：发送兑换码 + 网址 + 注册说明
  → 用户打开网站 → 注册账号（邮箱+密码）
  → 进入兑换页面 → 输入兑换码
  → LeanCloud验证：码存在？未被使用？
  → 验证通过 → 标记码为已用 → 账号 unlocked 写入对应课程
  → 页面提示"解锁成功！" → 自动跳转内容页
  → 永久可看，购买后内容维护更新老用户同步享受

退款流程：
小红书退款成功
  → 登录 LeanCloud 后台
  → 找到该用户 → unlocked 清空对应课程
  → 用户下次打开网站自动失去权限

换设备流程：
用户换手机/电脑
  → 打开网站 → 点登录 → 输邮箱+密码
  → 自动恢复权限（账号在服务器，不依赖本地缓存）

后期新系列上线流程：
出新系列课程（如护理系列）
  → LeanCloud CourseList 表加入新课程数据
  → 新课程网页引入 auth.js，传入 course_id
  → 生成新系列兑换码（type = nursing_basic 等）
  → 小红书上架新商品
  → 老用户（已买基础医学）需单独购买护理系列

七、页面清单（新增）
----------------------------------------------------------------
login.html          登录页（邮箱+密码+忘记密码入口）
register.html       注册页（邮箱+密码+确认密码）
redeem.html         兑换码输入页（输入码 → 解锁）
account.html        个人中心（邮箱 + VIP状态 + 永久有效）
auth.js             统一权限检查脚本（所有课程页面引入）

注：不需要 pay.html，支付在小红书完成，网站不涉及收款

八、内容锁定方式
----------------------------------------------------------------
免费内容：每门课第1章、第2章，所有人可看
付费内容：第3章起，必须登录且已解锁该课程才能看

锁定效果：
- 未登录访问付费章节 → 跳转 login.html，提示"请先登录"
- 已登录但未解锁 → 显示章节标题+简介，内容区显示锁定提示和解锁引导
- 已解锁 → 正常显示全部内容

锁定提示区样式：
  章节标题和简介正常显示（激发好奇心）
  内容区显示：🔒 此章节需要解锁
             "已购买？输入兑换码解锁 →"
             "还没购买？去小红书获取 →"

- 导出用户数据

十一、扩展性设计（重要）
----------------------------------------------------------------
【扩展场景预判】
- 后期增加新课程（如生化、免疫、内科）
- 后期增加新套餐（如全站通票、单科升级）
- 后期增加新内容类型（书籍资料、工具软件、视频）
- 后期可能引入付费墙升级（更高级会员）

【扩展性方案】

方案1：vip_type 字段设计为数组/标签
  当前：vip_type = "all" 或 "anatomy"
  扩展后：vip_type = ["anatomy", "physiology", "biochemistry"]
  好处：一个字段支持任意组合的课程权限，加新课不改代码

方案2：课程注册表（LeanCloud 新建 CourseList 表）
  字段：
    course_id       课程唯一标识（如 anatomy / biochemistry）
    course_name     课程名称
    free_chapters   免费章节数（默认2）
    is_active       是否上线（true/false）
    price_single    单科定价
  好处：上线新课程只需后台加一行数据，不改代码

方案3：兑换码 type 字段对应课程ID
  当前：type = "all" / "anatomy"
  扩展：type = "biochemistry" / "bundle_medical5"（5门课包）
  好处：任意新增套餐，只需生成对应type的兑换码

方案4：内容类型扩展（书籍/工具/视频）
  LeanCloud 用户表增加：
    content_access  已解锁内容列表（数组）
    如：["medical4", "books_basic", "tools_pack"]
  好处：不同类型内容权限独立管理，互不干扰

【前端扩展规范】
- 每门课网页顶部统一加一段权限检查JS（独立文件 auth.js）
- auth.js 读取 LeanCloud 用户 vip_type，判断当前课程是否解锁
- 新增课程只需引入 auth.js + 传入 course_id，无需重复写逻辑
